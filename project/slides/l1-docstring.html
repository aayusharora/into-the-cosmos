Lesson 1

Ask for Mars, get a spacecraft

COMMAND='Mars'

Multiple major-bodies match:

    4   Mars Barycenter

  499  Mars

   -3  Mars Orbiter Mission

  -41  Mars Express

No sky data. And no error either.

body: {"description":

  "JPL code, not the name.

  499 Mars, 699 Saturn."}

→ 79° altitude, magnitude 0.78

One sentence of English. First try.

Your schema, your service names, your table called accounts that everyone calls customers. The description is the only place any of that can live.

This is where the talk stops being advice and starts being evidence. Say that. The model does the obvious thing: it asks for Mars. And JPL comes back with four things called Mars: the barycentre, the planet, and two spacecraft that are orbiting it right now. Ask for Mars, get a spacecraft. Now the part that matters: that's not an error. No exception, no 400, no "bad request". It's a perfectly successful HTTP response containing a menu. Your code reads it looking for an ephemeris, finds none, and returns nothing useful. The model has no idea why. The fix is one sentence on the parameter: it takes a JPL code, not a name, and here are two examples. Then make it theirs, slowly: nobody's model has heard of your internal service names, or that your customers table is called accounts. There's no recovery path for those. The description is the only place that knowledge can exist. If asked whether this is just prompt engineering: no. It's on the function, so it travels with the tool into every agent that imports it.
