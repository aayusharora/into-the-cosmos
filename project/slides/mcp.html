Ninety seconds, and don't oversell it. Everything so far has been tools I wrote. In real life you won't own all of them. Somebody has already built the one you need, and MCP is how you plug it in without writing it. The shape is the slide. A name and a URL. From the loop's point of view nothing changes: the model still asks for a tool by name, you still run the round trip, you still hand the result back. Then the three constraints, and all three came out of the SDK this afternoon rather than from a blog post. Remote only. There's no stdio transport in the type at all, so the local servers people run on their laptops aren't what this is. Streamable HTTP, a url and headers, and that's the entire surface. And the one to say slowly, because half this room will be on Google Cloud: the SDK's own docstring says this type isn't supported in Vertex AI. So the enterprise path and the MCP path aren't the same path today. Worth checking before you design around it. If someone asks for a public server to try: don't name one from memory. Test it the morning of.
